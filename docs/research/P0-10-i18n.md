# P0-10: ICU4X・fluent-rsの統合

- **調査日:** 2026-11-08
- **状態:** Linuxと、Android（arm64のビルド、x86_64エミュレーターでの実行）で確認済み。iOSは保留。方式は[ADR-0007](../adr/0007-i18n.md)。
- **目的:** 統合開発計画 §18（Locale、UIの多言語化、Unicode処理、検索・並べ替え）の基盤として、ICU4Xとfluent-rsのバイナリサイズの増加、データの同梱方式、Localeのフォールバックを確認する。
- **確認プログラム:** [`spikes/p0-10-i18n/`](../../spikes/p0-10-i18n/)（機能ごとのcargo feature）

## 1. 対象

| crate | 版 | ライセンス |
|---|---|---|
| ICU4X（`icu_segmenter`、`icu_collator`、`icu_normalizer`、`icu_locale`、`icu_plurals`、`icu_decimal`、`icu_datetime`） | 2.4.0（2026-10） | Unicode-3.0 |
| `fluent-bundle` | 0.16.0（2025-05） | Apache-2.0 OR MIT |
| `fluent-langneg` | 0.13.1（`fluent-bundle` 0.16が使う版） | Apache-2.0 OR MIT |

依存crateのライセンスはADR-0011の許可リスト内（`self_cell` の `Apache-2.0 OR GPL-2.0-only` はApache-2.0を選べる）。

データはICU4Xの既定（`compiled_data`。全Localeのデータをバイナリに埋め込む）を使った。

## 2. 動作

| 機能 | 入力 | 結果 |
|---|---|---|
| Localeのフォールバック | `ja-JP` | `ja-JP → ja → und` |
| | `zh-Hant-HK` | `zh-HK → zh-Hant → und` |
| | `pt-AO` | `pt-AO → pt-PT → pt → und`（CLDRの親Locale） |
| | `en-GB` | `en-GB → en-001 → en → und` |
| 単語の分割（自動） | `今日は良い天気です。` | `今日`／`は`／`良い`／`天気`／`です`／`。`（辞書） |
| | `中文分词测试` | `中文`／`分词`／`测试` |
| | `ภาษาไทยสวัสดีครับ` | `ภาษา`／`ไทย`／`สวัส`／`ดี`／`ครับ`（`สวัสดี` が分割された） |
| 行の分割（禁則） | `「こんにちは。」と言った。…` | 開き括弧は次の文字と、句点・閉じ括弧は前の文字と分割されなかった |
| 照合（`ja`） | `カ か あ ア 亜 b A ä a` | `a A ä b あ ア カ か 亜`（ルートの照合では `か カ` の順） |
| 正規化 | `é`（結合文字）、`が`、`ｶﾞ` | NFC・NFDの変換と往復の一致を確認 |
| 複数形 | `ru`、`ar`、`en`、`ja` | `ru` の one/few/many、`ar` の zero/one/two/few/many/other を区別した |
| 数値 | `ja`、`de`、`ar-EG`、`hi-IN` | `1,234,567`、`1.234.567`、`١٬٢٣٤٬٥٦٧`、`12,34,567` |
| 日付 | `ja`、`en-US`、`ar-EG`、`ja-u-ca-japanese` | `2026年11月8日`、`November 8, 2026`、`٨ نوفمبر ٢٠٢٦`、`令和8年11月8日` |
| Fluent（UIの文言） | 要求 `ja-JP`、`ru`、`fr-CA` | 言語の連鎖（例: `ja → en-US`）を作り、日本語に無い文言は英語にフォールバックした。`ru` の複数形を区別した |

## 3. バイナリサイズ（Linux x86-64、release、strip後）

| 構成 | サイズ | 基準からの増加 |
|---|---|---|
| 基準（ICU4X・Fluentなし） | 0.39 MB | — |
| 文字境界（単語・行。日本語・中国語の辞書、東南アジアの文字体系のLSTMを含む） | 2.83 MB | **+2.44 MB** |
| 照合 | 1.65 MB | +1.26 MB |
| 日付 | 1.55 MB | +1.17 MB |
| Fluent | 0.71 MB | +0.32 MB |
| 正規化 | 0.46 MB | +0.08 MB |
| Localeのフォールバック | 0.45 MB | +0.06 MB |
| 複数形 | 0.44 MB | +0.06 MB |
| 数値 | 0.45 MB | +0.06 MB |
| すべて | 5.67 MB | **+5.28 MB** |

Android arm64（`cargo ndk -t arm64-v8a`、release、strip後）: 基準 0.32 MB、文字境界 +2.44 MB、照合 +1.25 MB、日付 +1.15 MB、Fluent +0.30 MB、すべて +5.22 MB。デスクトップとほぼ同じだった。Android（x86_64エミュレーター）での出力はLinuxとバイト単位で一致した（P0-13）。

全Localeのデータを含む値である。必要なLocaleに絞ったデータ（ICU4Xのデータ生成ツールによる）や、実行時に読み込む方式（blob）の場合の値は計測していない。

## 4. 気づいた点

- **Fluentの依存がICU4Xと重複する。** `fluent-bundle` 0.16は、複数形の規則に `intl_pluralrules`、言語タグに `unic-langid` を使う。ICU4Xの `icu_plurals`・`icu_locale` とは別の実装・別のデータになる。
- **fluent-langnegの版が分かれている。** 最新の `fluent-langneg` 0.14.2はICU4Xの旧版（1.x）の `icu_locid` に移行しており、`fluent-bundle` 0.16（`fluent-langneg` 0.13・`unic-langid`）と型が合わない。組み合わせると、ICU4Xの1.xと2.xが同時に入る。
- タイ語の単語の分割（LSTM）で、`สวัสดี` が2つに分割された。検索用の分割（統合開発計画 §18.7）では、言語別の形態素解析・辞書（§18.8の自然言語拡張）を追加できる構造が必要になる。
- 照合の順序は、`ja` とルートで仮名の順が異なった。期待する順序は、検索・並べ替えの要件で定める。

## 5. 結論

- ICU4X 2.4は、§18のLocale・フォールバック・文字境界・照合・正規化・数値・日付の要件を満たす機能を持つ。
- サイズの大部分は文字境界・照合・日付のデータで、全Localeを含めると約5.3 MBになる。モバイル向けには、Localeを絞ったデータ、または実行時に読み込むデータの計測が必要。
- UIの文言はFluentで扱えるが、Localeのフォールバックの連鎖はICU4Xで作り、Fluentは文言の書式化だけに使うことで、`fluent-langneg` の版の問題を避けられる。複数形の規則の重複（`intl_pluralrules`）は残る。
