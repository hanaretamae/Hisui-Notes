## 1. 公式ヘルプに記載されている事実

### 1.1 見出しリンク

- リンク先の末尾に `#` と**見出しの文字列そのもの**を付ける。例: `[[About Obsidian#Links are first-class citizens]]`。スラッグ化（小文字化・記号除去）は記載されていない。
- サブ見出しは `#` を重ねる。例: `[[Help and support#Questions and advice#Report bugs and request features]]`。
- 同じノート内の見出し: `[[#見出し]]`。
- 例はすべてWikilink形式。Markdown形式の見出しリンクの例はない。

### 1.2 ブロックリンク

- リンク先の末尾に `#^` とブロック識別子を付ける。例: `[[2023-01-01#^37066d]]`。
- ブロック参照はObsidian固有であり、Obsidian以外では動作しないと明記されている。

### 1.3 ブロック識別子

- 使用可能な文字: 「Latin letters, numbers, and dashes」のみ。
- 段落: 行末に空白1つと `^識別子` を置く。
- リスト、引用、コールアウト、表などの構造化ブロック: 識別子を独立した行に置き、前後に空行を入れる。
- 個別のリスト項目: その行末に置ける。
- 引用・コールアウト・表の一部分へのリンクは非対応。

### 1.4 Markdown形式のリンクとパス

- Markdown形式では、リンク先をURLエンコードする（例: 空白は `%20`）。
- フォルダパスはVaultルート起点で、Windowsでも `/` を使う。例: `[Three laws of motion](Projects/Three%20laws%20of%20motion.md)`。
- 拡張子 `.md` は省略可能（省略形と同等と記載）。
- 既定はWikilink形式で生成する。設定「Use [[Wikilinks]]」を無効にするとMarkdown形式で生成する。
- 「Automatically update internal links」設定がある。
- `# | ^ : %% [[ ]]` を含む文字列はリンクとして動作しない場合がある（「禁止」ではなく「may not work」）。

## 3. 「日本語を使えるようにする」要求との関係

### 3.1 見出しリンク

Obsidianは見出し文字列をそのままアンカーに使うため、日本語見出しへのリンクはObsidianの方式と矛盾しない。GitHub方式のスラッグ化（`## 日本語の見出し` → `#日本語の見出し`、記号除去・小文字化）とは結果が異なる。

### 3.2 ブロック識別子

**Obsidianのブロック識別子はASCIIの英字・数字・ハイフンに限られ、日本語を使えない。** フォーラムでは、キリル文字、北欧文字、アクセント付き文字、漢字が認識されない報告がある。Hisui Notesでブロック識別子に日本語を許可すると、そのリンクはObsidianで解決されない。

## 4. 方針案

> **決定（2026-11-08）:** 見出しアンカーは§4.1の方式、ブロック識別子は**案B（ASCIIのみ）**、`^` は両形式を読み取る方式を採用した。生成時の符号化は§5の確認後に決める。正本は [ADR-0009](../adr/0009-link-anchor-format.md)。以下は検討時の記録として残す。

### 4.1 見出しアンカー（D-06）

- アンカーは見出し文字列そのものとする（Obsidian方式）。スラッグ化しない。
- 読み取り時は、見出し文字列（符号化あり・なし）と、GitHub方式のスラッグの両方で解決を試みる。GitHub方式で解決した場合は互換解決として扱う。
- 生成時の符号化範囲は、Obsidianでの実機確認（§5）の結果で決める。候補:
  - (a) 空白・`(`・`)`・`%`・`<`・`>`・制御文字のみ符号化し、日本語はそのまま書く。原文が読みやすい。
  - (b) RFC 3986に従い非ASCII文字もすべて符号化する。互換性は高いが、日本語が `%E8%A6%8B…` になり原文が読めない。
- 同名見出しは、上位見出しを `#` で連結した経路で区別する方式を候補とする（Obsidianで動作するか要確認）。

### 4.2 ブロック識別子

選択肢:

| 案 | 内容 | Obsidian互換性 | 日本語 |
|---|---|---|---|
| A | Unicodeの文字・数字・ハイフンを許可する。自動生成IDはASCII。設定「Obsidian互換」を有効にすると、非ASCIIの手動IDに警告を出す | 非ASCIIのIDのみ非互換 | 使える |
| B | ASCIIの英字・数字・ハイフンのみ許可する。日本語はリンクの表示文字列で扱う | 完全互換 | IDには使えない |

推奨はA。日本語を使える要求を満たし、互換性が必要な利用者には警告で知らせられる。どちらを採るかは要決定。

### 4.3 `^` の符号化（D-07）

- 読み取りは `#^id` と `#%5Eid` の両方を受け付ける。
- 生成形式はObsidianでの実機確認（§5）の結果で決める。

## 5. 実機確認の結果（P0-14）

### 5.1 方法

- **対象:** Obsidian 1.14.5（Electron 43.8.3、Linux、nixpkgs版）。
- **環境:** 利用者の既存設定に触れないよう、`XDG_CONFIG_HOME` を一時ディレクトリに向けて別プロファイルで起動した。検証用Vaultは一時ディレクトリに作成した。Vault設定は `useMarkdownLinks: true`、`newLinkFormat: "relative"`。
- **手順:** `--remote-debugging-port` で起動し、Chrome DevTools Protocolで次を取得した。
  - ファイルの解決: `app.metadataCache.getFileCache().links` と `getFirstLinkpathDest()`。
  - 見出し・ブロックの解決: `app.workspace.openLinkText()` でリンクを開き、移動後のカーソル行を記録した。見出しが1行目にあると「解決した」と「解決できずに先頭を開いた」を区別できないため、対象ファイルの先頭に前置きの行を入れて確認した。
  - Obsidianが生成する形式: `app.fileManager.generateMarkdownLink()`。
  - 名前変更時の書き換え: `app.fileManager.renameFile()`。

### 5.2 リンクの解決

対象ファイルの見出し・ブロックの位置は、`# 見出し` が3行目、`## Heading with space` が7行目、`### 重複` が17行目（`## 親A` の下）と23行目（`## 親B` の下）、`## 括弧(テスト)` が27行目、`段落です。 ^abc123` が31行目。

| # | リンク | 結果 |
|---|---|---|
| 1 | `[a](対象.md#見出し)`（日本語をそのまま書く） | 解決（3行目） |
| 2 | `[a](%E5%AF%BE%E8%B1%A1.md#%E8%A6%8B%E5%87%BA%E3%81%97)` | 解決（3行目）。Obsidianは読み取り時に復号する |
| 3 | `[a](<対象.md#Heading with space>)`（山括弧、空白をそのまま書く） | 解決（7行目） |
| 4 | `[a](対象.md#Heading%20with%20space)` | 解決（7行目） |
| 5 | `[a](対象.md#^abc123)`（`^` をそのまま書く） | 解決（31行目） |
| 6 | `[a](対象.md#%5Eabc123)` | 解決（31行目） |
| 7 | `[a](<my note.md>)` | 解決 |
| 8 | `[a](my%20note.md)` | 解決 |
| 9 | `[a](./ノート/会議メモ.md)` | 解決 |
| 10 | `[a](<./ノート/会議メモ.md#議題と決定事項>)` | 解決（見出し行） |
| 11 | `[a](対象.md#親A#重複)`（上位見出しを連結） | 解決（17行目、親Aの下の見出し） |
| 12 | `[a](<対象.md#括弧(テスト)>)` | 解決（27行目） |
| 13 | `[a](対象.md#括弧(テスト))`（対応の取れた括弧をそのまま書く） | 解決（27行目） |
| 14 | `[a](<./my note.md#スペース入り>)` | 解決（見出し行） |
| 15 | `[a](対象.md#^ABC123)`（大文字） | 解決（31行目）。ブロックIDは大文字・小文字を区別しない |
| 16 | `[a](対象.md#存在しない)` | ファイルは開くが見出しは未解決（1行目を開く） |
| 17 | `[a](対象.md#重複)`（同名見出し） | 最初の見出し（17行目）に解決 |
| 18 | `[a](対象.md#heading-with-space)`（GitHub方式のスラッグ） | 見出しは未解決（1行目を開く） |
| 19 | `[a](対象.md#^存在しない)` | ブロックは未解決（1行目を開く） |

ブロック識別子: `^abc123` のみ認識された。`^日本語` と `^ab_cd`（下線）は認識されなかった（`metadataCache` の `blocks` に含まれない）。公式ヘルプの「英字・数字・ハイフンのみ」と一致する。

### 5.3 Obsidianが生成する形式

`newLinkFormat` が `relative`・`shortest`・`absolute` のいずれでも、表記の規則は同じだった（パスの起点だけが変わる）。

| 対象 | 生成結果（`relative`） |
|---|---|
| 日本語のファイル名 | `[対象](対象.md)` |
| 空白を含むファイル名 | `[my note](my%20note.md)` |
| 日本語の見出し | `[対象](対象.md#見出し)` |
| 空白を含む見出し | `[対象](対象.md#Heading%20with%20space)` |
| 括弧を含む見出し | `[対象](対象.md#括弧(テスト))` |
| 同名見出し | `[対象](対象.md#親A#重複)` |
| ブロック | `[対象](対象.md#^abc123)` |
| 下位フォルダから上位のファイル | `[対象](../対象.md#見出し)` |

Obsidianは日本語・`^`・括弧を符号化せず、空白だけを `%20` にする。`relative` でも先頭に `./` は付けない。

### 5.4 名前変更時の書き換え

`my note.md` を `renamed note.md` に変更したとき、Obsidianはリンクを次のように書き換えた。

| 変更前 | 変更後 |
|---|---|
| `[a](<my note.md>)` | `[a](<renamed note.md>)`（山括弧の形式を維持） |
| `[a](my%20note.md)` | `[a](renamed%20note.md)` |
| `[a](<./my note.md#スペース入り>)` | `[a](<renamed note.md#スペース入り>)`（`./` が削除される） |

### 5.5 結論

- ADR-0009 §5の規則（URLエンコードしない。空白などは山括弧の形式を使う）で生成したリンクは、確認した範囲ですべてObsidianで解決される。
- Obsidianとの表記の違いは、空白を含むリンク先（Obsidianは `%20`、Hisui Notesは山括弧の形式）と、先頭の `./`（Obsidianは付けない）の2点。どちらも相互に解決できる。
- Obsidianで名前を変更すると、Hisui Notesが書いた `./` が削除される。解決には影響しない。
- GitHub方式のスラッグはObsidianでは解決されない。Hisui Notesでの読み取り時の互換解決（ADR-0009 §1）はHisui Notes内だけの機能になる。
- 同名見出しは、上位見出しを連結した `#親#子` で区別できる。Obsidianも同名見出しへのリンクをこの形式で生成する。
