# P0-07: プラグインABIと権限制御

- **調査日:** 2026-11-08
- **状態:** 完了。ABIの方式は[ADR-0006](../adr/0006-plugin-abi.md)。
- **目的:** ADR-0005で決めたWasmi上で、コアモジュール + 独自ABIにより、ADR-0008の権限モデル（既定拒否、範囲、確認、取り消し、主体の偽装防止）を強制できるかを確認する。完了条件は「許可されていないホスト関数の呼び出しを拒否できる」（実行計画 P0-07）。
- **確認プログラム:** [`spikes/p0-07-plugin-abi/`](../../spikes/p0-07-plugin-abi/)（再現手順は同ディレクトリのREADME）

## 1. 検証したABI（v1）

- インポートはモジュール名 `hisui:v1` の**関数のみ**。メモリ・テーブル・グローバルのインポートと、WASIを含む他のモジュール名は拒否する。
- 必須のエクスポート: `memory`、`hisui_abi_version() -> i32`（1を返す）、`run(i32) -> i64`。
- 文字列・バッファは（ポインター, 長さ）で受け渡す。ホストは拡張のメモリから読む前に範囲を検査する。1回の引数の上限は64 KiB。
- 戻り値が負の場合はエラーコード（`-1` 拒否、`-2` 存在しない、`-3` 引数が不正、`-4` 出力先が小さい、`-5` 確認UIが無い）。
- ホスト関数と必要な権限の対応表をホストが持つ（`log`: なし、`vault_read`: `vault.read`、`net_connect`: `net.connect`）。
- 主体IDはホストが読み込み時に割り当てる（`extension:<マニフェストのID>`）。ホスト関数の引数に主体は無く、拡張は主体を指定できない。
- マニフェストは検証ではホスト側の値とした（配布形式は未定）。

## 2. 方法

権限の付与: `extension:sample` に `vault.read`（範囲 `notes`）と `net.connect`（`https://example.com`）を付与した。Vaultはメモリ上の模擬（ファイルシステムは使わない）。燃料とメモリ上限（16 MiB）を有効にした。

- 実行時の検査: Rustで書いたプラグイン（`wasm32-unknown-unknown`、33 KB）から各種のパスを読む。
- 読み込み時の検査: WATで書いた不正なモジュールを読み込む。
- 不正な引数: WATで、範囲外のポインター・桁あふれ・上限超過・不正なUTF-8を渡す。
- 性能: `check()` を100万回、拡張からの `vault_read` を10万回（Pコアに固定）。

## 3. 結果（25項目すべて期待どおり）

### 3.1 実行時の権限検査

| 操作 | 期待 | 結果 |
|---|---|---|
| `notes/a.md`（範囲内） | 許可 | 許可、内容を返した |
| `notes/./a.md`（正規化で範囲内） | 許可 | 許可 |
| `notes/missing.md`（範囲内、存在しない） | 存在しない | `-2` |
| `notes/../secret.md`（`..`） | 拒否 | `-1` |
| `/etc/passwd`（絶対パス） | 拒否 | `-1` |
| `private/b.md`（範囲外） | 拒否 | `-1` |
| `notes2/x.md`（文字列の接頭辞だけ一致） | 拒否 | `-1`（範囲はパスの要素単位で照合） |
| `Notes/a.md`（大文字・小文字の違い） | 拒否 | `-1` |
| `net.connect`（external、確認UIなし） | 拒否 | `-5`（ADR-0008 §4） |
| 付与の取り消しの直後の読み取り | 拒否 | `-1`（即時に反映） |
| 監査ログ | 文書内容を含まない | 主体・権限・範囲・結果のみ |

### 3.2 読み込み時の検査（インスタンス化の前に拒否）

| モジュール | 結果 |
|---|---|
| マニフェストで宣言していない権限の関数（`net_connect`）をインポート | `UndeclaredCapability` |
| WASIの関数（`wasi_snapshot_preview1.fd_write`）をインポート | `ForbiddenImport` |
| 存在しないホスト関数（`process_spawn`）をインポート | `UnknownHostFunction` |
| ホストのメモリをインポート | `ForbiddenImport` |
| ABIの版が2 | `AbiVersion(2)` |
| 必須のエクスポートが無い | `MissingExport` |
| WASMとして不正なバイト列 | `Invalid` |

### 3.3 不正な引数（ホストは停止せず、エラーコードを返した）

| 引数 | 結果 |
|---|---|
| パスのポインターが範囲外 | `-3` |
| パスの長さが上限超過 | `-3` |
| ポインター + 長さの桁あふれ | `-3` |
| 出力先が範囲外 | `-3` |
| 出力先が小さい | `-4` |
| UTF-8として不正なパス | `-3` |

### 3.4 性能

| 項目 | 結果 |
|---|---|
| `check()` 1回 | 84 ns（ADR-0008 §9の目標1 µs以下） |
| 拡張からの `vault_read` 1回（境界の検査、権限検査、監査ログへの追加、コピーを含む） | 360 ns |

検証用の実装は検査のたびに文字列を確保しており、最適化の余地がある。ハンドル方式・世代番号（ADR-0008 §9）は実装していない（検証では毎回検査）。

## 4. 結論

- Wasmiのコアモジュールと独自ABIで、ADR-0008の強制（既定拒否、宣言と付与、範囲、確認、取り消し、主体の偽装防止）を実現できる。完了条件を満たす。
- 強制は「読み込み時のインポートの検査」と「ホスト関数ごとの `check`」の2段で行う。読み込み時の検査により、宣言していない権限・WASI・未知の関数を使うモジュールはインスタンス化されない。
- ABIの詳細（関数一覧、エラーコード、マニフェストの形式と配布、版の互換性）はADR-0006とSpecで定める。

## 5. 未確認の事項

- 実際のファイルシステムでの範囲照合（シンボリックリンク、Unicode正規化の違い、大文字・小文字を区別しないファイルシステム）。ADR-0008の検証項目として、Property-based Testingで行う。
- ハンドル方式と世代番号による失効の実装と計測。
- 確認UIがある場合の `Confirm` の扱い（Command Surface）。
- パーサー拡張のABI（ADR-0004 §3の規則の登録と呼び出し）。本検証はユーザープラグインの形を対象とした。
- マニフェストの配布形式（WASMのカスタムセクション、または別ファイル）と署名。
