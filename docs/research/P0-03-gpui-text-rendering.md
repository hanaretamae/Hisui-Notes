# P0-03: GPUIのテキスト描画（Linux）

- **調査日:** 2026-11-08
- **状態:** Linux（Wayland）で確認済み。Windows・macOSは保留（統合開発計画 §1.2）。
- **対象:** Zed `v1.27.0`（コミット `c84af5b9`、ADR-0001）。Linuxの文字の整形・描画は `gpui_wgpu` のcosmic-textによる実装。
- **確認プログラム:** [`spikes/p0-02-03-gpui-text/`](../../spikes/p0-02-03-gpui-text/) の `render`

## 1. 方法

17種類の文字列を20 pxで1行ずつ表示し、利用者が目視で確認した。同時に、GPUIの `shape_line` の結果（字形の一覧と、各字形の原文の位置・表示位置）を次の観点で自動的に調べた。

- 字形が無い文字（`.notdef`、字形ID 0）の数
- 表示上の左から右の順に並べたときの、原文の位置の順序
- 書記素クラスタの境界ごとの `x_for_index`（原文の位置 → 表示位置）と `closest_index_for_x`（表示位置 → 原文の位置）の往復

インストール済みのフォント: 日本語（UDEV Gothic等）、Noto CJK、Noto Sans Arabic・Hebrew・Devanagari・Tamil・Thai、Noto Color Emoji、Adwaita Sans（既定）。

- **整形と描画:** すべての文字体系で、利用者の目視で問題は無かった。フォールバックによる別フォントの使用、アラビア語の文字の連結、インド系文字の結合子音、絵文字の連結が行われている。
- **双方向テキスト:** 並べ替えは行われる。`abc مرحبا 123 def` は、表示上「abc」「123」「アラビア語（右から左）」「def」の順になり、Unicodeの双方向テキストの規則（アラビア文字の後の数字の扱い）と一致した。段落の方向は最初の強い方向性の文字で決まっている（`עברית 2026 ABC` は右から左の段落）。
- **原文の位置:** 各字形は原文のバイト位置を持つ（`ShapedGlyph::index`）。字形から原文への対応は取れる。

## 3. 制約

- **右から左のテキストで、表示位置と原文の位置の変換が成り立たない。** アラビア語・ヘブライ語では `closest_index_for_x` がほぼすべて0を返し、`x_for_index` は表示上の左から右に単調に増えない。GPUIの `LineLayout` の変換関数は左から右の配置を前提としていると考えられる。クリックによるカーソルの配置、カーソル移動、選択範囲の表示は、Hisui Notes側で字形の一覧（原文の位置と表示位置）から計算し直す必要がある。
- タイ語で往復が一致しない境界が2か所あった（上付きの母音を含む書記素）。
- 異体字セレクターは独立した字形として出力され、その境界の往復が一致しなかった。
- 結合記号に対応する字形がフォントに無い場合（`가̂`）、`.notdef` が出力される。利用者の目視では表示の問題とは感じられなかった。
- フォールバックで使われたフォントの名前は、`get_font_for_id` では取得できなかった（`None`）。

## 4. 設計への影響（提案。Specで決める）

- カーソル位置・選択範囲・クリック位置の計算は、GPUIの `x_for_index`・`closest_index_for_x` に頼らず、字形の一覧と書記素境界（ADR-0003）から行う層を `ui-gpui` に置く。双方向テキストでの論理順・表示順のカーソル移動の方式は、統合開発計画 §18.5のSpecで定める。
- 双方向テキスト・タイ語・異体字セレクターの境界を、カーソル位置の計算の試験に含める。
