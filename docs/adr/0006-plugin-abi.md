# ADR-0006: プラグインABIと権限の強制方式

- **Status:** 採用（Accepted）
- **日付:** 2026-11-08
- **関連:** 統合開発計画 §6.2、§19／実行計画 P0-07／[`research/P0-07-plugin-abi.md`](../research/P0-07-plugin-abi.md)／ADR-0004、ADR-0005、ADR-0008

## Context

ADR-0005でWASMランタイムにWasmiを採用し、Component Modelを使わないため、拡張（ユーザープラグイン、パーサー）とホストの間は、コアモジュールと独自のABIで接続する。ADR-0008は、保護対象へのアクセスをホストサービス経由に限り、既定拒否・宣言と付与・範囲・確認・取り消し・主体の偽装防止を求める。

P0-07で、Wasmi上の独自ABIにより、これらを強制できることを確認した（25項目すべて期待どおり、`check()` 84 ns）。

## Decision

### 1. ABIの形

- 拡張は `wasm32-unknown-unknown` のコアモジュールとする。WASIは使わない。
- インポートは、ホストが定めるモジュール名（`hisui:v<主版>`）の関数のみとする。メモリ・テーブル・グローバルのインポートと、他のモジュール名のインポートを持つモジュールは読み込まない。
- 拡張は `memory` と `hisui_abi_version()` をエクスポートする。拡張体系ごとの必須のエクスポート（ユーザープラグインの入口、パーサーの規則関数など）は各体系のSpecで定める。
- 文字列・バッファは（ポインター, 長さ）で受け渡し、文字列はUTF-8とする。ホストは拡張のメモリを読み書きする前に範囲を検査し、1回の受け渡しの上限を設ける。
- ホスト関数の戻り値は、負の値をエラーコードとする共通の規約に従う。エラーコードの一覧はSpecで定める。
- ABIの版は主版・副版で管理する。主版の変更はモジュール名を変える（`hisui:v2`）。副版では関数の追加のみを行う。

### 2. 権限の強制

- ホスト関数ごとに必要な権限を、ホスト側の対応表で定める。
- **読み込み時:** インスタンス化の前に、モジュールのインポートを検査する。マニフェストで宣言していない権限の関数、存在しない関数、許可されていないインポートを持つモジュールは読み込まない。
- **実行時:** 権限を要するホスト関数は、呼び出しごとに Permission Broker の `check`（ADR-0008 §5）を通す。性能はADR-0008 §9のハンドル方式・世代番号で確保する。
- 主体IDはホストが読み込み時に割り当て、ホスト関数の引数に主体を含めない。
- 拡張からの不正な引数（範囲外、桁あふれ、上限超過、不正なUTF-8）は、エラーコードで返し、ホストを停止させない。

### 3. マニフェスト

- 拡張は、ID、版、ABIの版、必須権限・任意権限（ADR-0008 §3）、使用するシークレットのキー（ADR-0008 §6）を宣言する。
- 配布形式（WASMのカスタムセクション、または別ファイル）と署名は、拡張の配布を設計する時点で決める。

## Alternatives

1. **Component Model（WIT）。** 型付きのインターフェース定義と言語間のバインディング生成が使えるが、ADR-0005で採用したWasmiでは使えない。
2. **インポートの検査を行わず、ホスト関数の中の `check` だけで拒否する。** 実行時の検査だけでも拒否はできるが、宣言していない権限を使おうとするモジュールを読み込み時に検出できず、利用者への提示（インストール時の権限の一覧）とモジュールの内容が食い違う可能性が残る。

## Consequences

- 型の定義とバインディングを自前で用意する必要がある。拡張作者向けに、Rustのバインディング（SDK）を提供する。
- 読み込み時の検査により、マニフェストに無い権限を使う拡張は動作しない。
- ABIの版の互換性の管理が必要になる。
