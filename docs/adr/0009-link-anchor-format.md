# ADR-0009: 内部リンク・見出しアンカー・ブロック識別子の形式

- **Status:** 採用（Accepted）。§5の表記がObsidian 1.14.5で解決されることをP0-14で確認済み
- **日付:** 2026-11-08
- **関連:** 統合開発計画 §6.3、§8／実行計画 D-06、D-07、D-08、D-09／[`research/obsidian-links.md`](../research/obsidian-links.md)

## Context

統合開発計画 §8は、内部リンクを相対パスのMarkdown Linkとし、見出しリンクで日本語を扱い、Obsidian互換のブロックリンクを提供すると定める。見出しアンカーの生成規則、ブロック識別子の使用文字、`^` の符号化、Obsidian拡張を無効化したときの扱い、ファイル移動時のリンク更新の責務が未定義だった。

Obsidianの公式ヘルプでは、見出しリンクは見出し文字列をそのまま使い、ブロック識別子は英字・数字・ハイフンに限られる。

## Decision

### 1. 見出しアンカー（D-06）

- アンカーは見出し文字列そのものとする（Obsidian方式）。スラッグ化しない。日本語の見出しはそのまま参照できる。
- 読み取り時は、(1) 見出し文字列の完全一致（パーセント符号化を復号して比較）、(2) GitHub方式のスラッグとの一致、の順に解決する。(2)で解決したリンクは互換解決として扱い、リンク補助で正規形への書き換えを提案する。GitHub方式のスラッグはObsidianでは解決されない（P0-14で確認）。
- 比較の前にUnicode正規化（NFC）を行う。原文は変更しない。
- 同名の見出しは、上位見出しを `#` で連結した経路（例: `#親A#重複`）で区別する。生成時は、同名の見出しがある場合に限り、一意になるまで上位見出しを連結する。経路のない同名見出しへのリンクは最初の見出しに解決する（Obsidianと同じ。P0-14で確認）。

### 2. ブロック識別子

- 使用可能な文字はASCIIの英字・数字・ハイフン（`[A-Za-z0-9-]+`）に限る（Obsidianと完全互換。案Bを採用）。
- 大文字・小文字を区別せずに一意性を判定する。
- 自動生成するIDは小文字英数字6文字とする。
- 日本語の説明はリンクの表示文字列で扱う。
- 配置規則はObsidianに合わせる（段落・リスト項目は行末、構造化ブロックは前後に空行を置いた独立行）。

### 3. `^` の読み取り（D-07）

- 読み取りは `#^id` と `#%5Eid` の両方を受け付ける。

### 4. 責務の分担

- **Obsidian拡張を無効化した場合（D-08）:** ブロックリンクの文字列を原文のまま保持し、リンク先のフラグメントは「解釈できない参照」として未解決表示する。原文は書き換えない。
- **ファイル移動・名前変更時のリンク更新（D-09）:**
  1. `vault` が移動前後のパスを含むイベントを発行する。
  2. `vault` のリンク索引から、移動したファイルを参照する文書と、移動したファイル自身（相対パスが変わるため）を特定する。
  3. 各文書の文書形式拡張が、リンク書き換えのテキスト編集の列を返す。`vault` は文書形式の構文を解釈しない。
  4. `vault` は全文書の編集を1つの操作として適用し、1回のUndoで元に戻せるようにする。
  5. 既定では、適用前に変更対象の文書一覧を表示して確認する。設定で確認を省略できる。

### 5. 生成時の表記（URLエンコードしない）

原文の可読性を優先し、内部リンクの生成ではパーセント符号化（URLエンコード）を行わない。日本語、空白、`^` などはそのまま書く。

CommonMarkのリンク先の構文上そのまま書けない文字は、次の規則で扱う。

1. リンク先に空白、ASCII制御文字、対応の取れない `(` `)` を含む場合、または `<` で始まる場合は、山括弧の形式 `[表示](<./my note.md#見出し 1>)` を使う。
2. 山括弧の形式の中の `<` と `>` はバックスラッシュでエスケープする（`\<`、`\>`）。
3. バックスラッシュ自体はエスケープする（`\\`）。
4. 改行を含むパス・見出しへのリンクは生成しない（エラーとして利用者に通知する）。
5. 上記以外はそのまま書く。例: `[段落](./ノート.md#^abc123)`、`[見出し](../資料/会議メモ.md#議題と決定事項)`。

読み取りでは、他のツールで作られたリンクとの互換のため、パーセント符号化されたリンク先も復号して解決する。符号化を含む文字列と同名のファイル（例: `a%20b.md`）が実在する場合は、復号前の文字列での一致を優先する。

既存のリンクを編集・更新する場合（ファイル移動時の書き換えなど）も、書き換えたリンクは本規則の表記にする。書き換えないリンクの表記は変更しない。

**互換性（P0-14で確認）:** 本規則で生成したリンク（符号化しない日本語、山括弧の形式、符号化しない `#^`、`./` 始まり、`#親#子`）は、Obsidian 1.14.5ですべて解決された。Obsidianは空白を `%20` で書き、`./` を付けない点が異なるが、相互に解決できる。Obsidianでファイル名を変更すると `./` が削除される（解決には影響しない）。詳細は [`research/obsidian-links.md`](../research/obsidian-links.md) §5。

## Alternatives

1. **GitHub方式のスラッグを正規形にする。** GitHubでのプレビュー互換性は高いが、Obsidianと不一致になり、日本語見出しの記号の扱いが曖昧になる。
2. **ブロック識別子にUnicodeを許可する（案A）。** 日本語を使えるが、Obsidianで解決されないリンクが生まれる。互換性を優先して採用しない。

## Consequences

- Obsidianで作成したVaultとHisui Notesで作成したVaultの間で、見出しリンク・ブロックリンクを相互に解決できる。
- ブロック識別子に日本語を使えない。
- リンク更新は文書形式拡張ごとに実装する必要がある。
