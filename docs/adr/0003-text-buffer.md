# ADR-0003: テキストバッファと編集履歴の方式

- **Status:** 採用（Accepted）
- **日付:** 2026-11-08
- **関連:** 統合開発計画 §5.2、§18.4、§22.1／実行計画 D-05／[`research/P0-09-text-buffer.md`](../research/P0-09-text-buffer.md)／[`requirements/non-functional.md`](../requirements/non-functional.md)

## Context

統合開発計画 §5.2は、Rope構造、Undo/Redo、インクリメンタルな変更通知、複数ビューからの編集、自動保存とクラッシュリカバリー、UTF-8・UTF-16・書記素位置の変換を求めている。D-05では、同期は実装しないが、編集を操作単位で記録する方式を採ると決めた。

P0-09で `ropey` 1.6.1と `crop` 0.4.3を比較し、両者とも性能要件を満たすこと、cropの書記素の処理に不具合があることを確認した。

## Decision

### 1. Rope

- `text-buffer` の内部実装に `ropey` 1.6.1を使う。
- `text-buffer` の公開APIの位置はUTF-8のバイト位置とする。ropeyの型と文字位置は公開APIに出さない。
- 位置変換（バイト、コードポイント、UTF-16、行・列、書記素クラスタ）は `text-buffer` が提供する。
- 文字境界でないバイト位置を受け取った場合は、パニックせずにエラーを返す。

### 2. 書記素クラスタ

- `unicode-segmentation` の `GraphemeCursor` をRopeのチャンク単位で使って実装する。
- カーソル移動・選択・削除は書記素クラスタ単位とする。ただし、結合文字の後退削除（Backspace）でコードポイント単位の削除を選べるかどうかはSpecで決める。

### 3. 編集の表現

- 1回の編集を「範囲置換」とする: 置換前のバイト範囲、削除された文字列、挿入された文字列。
- 複数カーソル・置換などの一連の変更は、範囲置換の列を1つのトランザクションとしてまとめる。トランザクション内の範囲は適用順に解釈する。
- 各トランザクションに、文書内で単調増加する版番号を付ける。

### 4. 操作列の共有（D-05）

範囲置換のトランザクション列を、次の用途で共有する。

| 用途 | 使い方 |
|---|---|
| Undo/Redo | 削除された文字列を保持しているため、逆操作を作れる。Undoの単位（入力の区切り）はトランザクションをまとめて決める |
| 変更通知 | パーサー、索引、ビューへ、版番号とトランザクションを通知する。受け手は差分だけを処理できる |
| クラッシュリカバリー | 最後の保存以降のトランザクションを端末内の記録へ追記する。起動時に、保存済みの内容へ適用して復元する |
| 将来の同期 | 範囲置換を、レプリカに依存しない位置表現（CRDT等）へ変換する余地を残す。同期は実装しない |

### 5. スナップショット

- ropeの複製（1回あたり数 µs）で、版番号付きの不変スナップショットを作る。
- 解析、索引、保存はスナップショットに対して行い、編集を止めない。
- 解析結果には、解析に使ったスナップショットの版番号を付ける。古い版の結果は、その後のトランザクションで位置を補正するか破棄する。

### 6. プライバシー

- クラッシュリカバリーの記録は端末内のアプリ専用の領域に保存し、正常に保存した後は削除する。
- 記録を外部に送信しない。

## Alternatives

1. **crop 0.4.3。** バイト位置が基本でAPIは合うが、書記素の処理に不具合があり、利用実績が少ない。
2. **ropey 2.0のベータ。** バイト位置が基本だが、安定版ではない。安定版の公開後に移行を検討する（公開APIをバイト位置にしているため、移行は `text-buffer` の内部で完結する）。
3. **ZedのropeまたはSumTreeによる自前実装。** Zedの `rope` はGPL-3.0で使えない。`sum_tree`（Apache-2.0）で自前のRopeを作ることはできるが、現時点で既存の実装で要件を満たせるため採用しない。
4. **CRDTを最初から採用する。** 同期は将来機能であり、今の時点で複雑さとメモリ使用量を増やす理由がない。

## Consequences

- 編集、Undo、変更通知、クラッシュリカバリーが同じ操作列を使うため、それらの整合性を1か所で検証できる。
- 公開APIをバイト位置にするため、ropeyの文字位置との変換が内部で発生する（1回あたり1 µs前後）。
- 書記素の処理を自前で持つため、チャンク境界のテスト（国旗、ZWJ連結、結合文字、結合子音）が必須になる。

## 検証

- Property-based Testing: 任意のトランザクション列を適用した後、Undoをすべて適用すると元の内容に戻る。Redoで再び同じ内容になる。
- Property-based Testing: 任意の位置で、バイト⇔UTF-16⇔コードポイント⇔行・列の変換が往復で一致する。
- 書記素: チャンク境界をまたぐ書記素クラスタで、`unicode-segmentation` の文字列全体での結果と一致する。
- クラッシュリカバリー: 記録の途中で終了した場合（記録の末尾が壊れている場合）も、壊れていない部分までを復元し、原文を失わない。
