# ADR-0007: 国際化基盤（ICU4X、Fluent）とデータの同梱方式

- **Status:** 採用（Accepted）
- **日付:** 2026-11-08
- **関連:** 統合開発計画 §18／実行計画 P0-10／[`research/P0-10-i18n.md`](../research/P0-10-i18n.md)／ADR-0002、ADR-0003、ADR-0011

## Context

統合開発計画 §18.10は、国際化処理にICU4X、UIの文言にProject Fluent（fluent-rs）を推奨している。P0-10で、ICU4X 2.4.0とfluent-bundle 0.16.0の動作とサイズを確認した。

- ICU4Xは、Localeのフォールバック、文字境界（日本語・中国語の辞書、行の禁則）、照合、正規化、複数形、数値、日付を、確認したすべての入力で期待どおりに処理した（タイ語の単語の分割に誤りが1件）。
- 全Localeのデータを埋め込むと、バイナリが約5.3 MB増える（文字境界 +2.4 MB、照合 +1.3 MB、日付 +1.2 MB）。
- `fluent-bundle` 0.16は `intl_pluralrules`・`unic-langid` を使い、ICU4Xと複数形の規則・言語タグの型が重複する。最新の `fluent-langneg` 0.14はICU4X 1.xに依存し、`fluent-bundle` 0.16と型が合わない。

## Decision

- 国際化処理（Locale、フォールバック、文字境界、照合、正規化、複数形、数値、日付）にICU4X 2.xを使う。書記素クラスタの処理はADR-0003の方式（`unicode-segmentation`）のままとし、単語・文・行の境界にICU4Xを使う。
- UIの文言は `fluent-bundle` で書式化する。言語の連鎖（フォールバック）はICU4Xの `LocaleFallbacker` と利用者の優先言語リストから作り、`fluent-langneg` は使わない。
- ICU4Xを使う処理は、ADR-0002の分割基準2に従い `intl` クレートに分ける（依存先が異なるため）。ICU4Xの型は `intl` の公開APIに出さない。
- データは、当面ICU4Xの既定（`compiled_data`、全Locale）を使う。モバイル向けのデータの絞り込み・実行時の読み込みは、Androidでの計測（P0-05・P0-13）の後に本ADRを改訂して決める。

## Alternatives

1. **Fluentを使わず、ICU4Xのメッセージ書式化で文言を扱う。** ICU4X 2.4の安定版のcrateに、Fluent相当のメッセージ書式化（複数形・選択・変数を含む文言の定義と翻訳資源の分離）があるかは確認していない（P0-10の対象外）。統合開発計画 §18.10はFluentを推奨している。
2. **`fluent-langneg` で言語の連鎖を作る。** 版の不整合（ICU4X 1.xへの依存）を持ち込む。
3. **最初からLocaleを絞ったデータを使う。** サイズは減るが、対応Localeの決定とデータ生成の手順が先に必要になる。

## Consequences

- §18の要件の大部分をICU4Xで満たせる。
- バイナリが約5.3 MB増える（デスクトップ、全Locale）。
- 複数形の規則がICU4XとFluent（`intl_pluralrules`）で重複する。
- タイ語など東南アジアの文字体系の単語の分割は、検索用には自然言語拡張（§18.8）で補う必要がある。
