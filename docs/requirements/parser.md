# 要件: パーサーと構文機能

- **状態:** 採用（2026-11-08）。構文機能の一覧は初版で、Spec作成時に詳細化する。
- **関連:** 統合開発計画 §6／ADR-0002、ADR-0004、ADR-0008、ADR-0009／調査: [`research/obsidian-syntax.md`](../research/obsidian-syntax.md)、[`research/obsidian-links.md`](../research/obsidian-links.md)

## 1. 構文機能の個別オン・オフ

### 1.1 要件

- **PR-01** パーサーは、自分が扱う構文を「構文機能（Feature）」の単位で宣言する。
- **PR-02** 各構文機能は、パーサー自身の設定でオン・オフできる。設定はパーサーの名前空間に属し、パーサーごとに独立する。
- **PR-03** 構文機能の宣言は、ID、表示名、説明、既定値、依存する構文機能を含む。設定UIは宣言からホストが生成する（パーサーごとにUIを実装しない）。
- **PR-04** 依存する構文機能をオフにした場合、それに依存する構文機能も無効になる。設定UIはその関係を表示する。
- **PR-05** 設定の適用範囲は「全体」と「Vault」とし、Vaultの設定が全体の設定より優先する。Vaultの設定はVault内の設定ディレクトリに保存し、Vaultとともに移動・共有できる。
- **PR-06** 構文機能をオフにしても原文を変更しない。その構文は、オフにした機能が無い場合の解釈（標準Markdownとしての解釈、または通常の文字列）として扱う。
- **PR-07** 構文機能のオン・オフを変更したら、開いている文書を再解析し、リンク・タグなどの索引のうち影響を受ける部分を更新する。
- **PR-08** パーサー全体の有効・無効（統合開発計画 §6.1）と、構文機能の個別のオン・オフは別の設定とする。パーサーを無効にした場合、そのパーサーの構文機能の設定は保持したまま適用しない。
- **PR-09** CommonMarkの基本構文は標準Markdownパーサーの必須部分とし、オフにできない。オフにできるのはCommonMarkに対する拡張とする。
- **PR-10** 構文機能のIDは変更しない。廃止する場合は、廃止した旨を宣言に残し、保存済みの設定を無視する。

### 1.2 性能

- **PR-11** 構文機能の判定は、解析の開始時に有効な構文機能の集合を一度決め、解析中に設定を参照しない。
- **PR-12** 構文機能の変更による再解析は、表示中の文書を優先し、それ以外の文書と索引はバックグラウンドで更新する。

### 1.3 パーサーの分離と組み合わせ

- **PR-40** 標準Markdown、Obsidian Markdown、各埋め込み言語のパーサーは、それぞれ独立したモジュールとし、他のパーサーに依存しない（ADR-0004 §2）。
- **PR-41** 拡張パーサーは、Obsidian Markdownパーサーと第三者のパーサー拡張を含め、同時に複数を有効にして組み合わせられる。組み合わせはホストを経由して行う（ADR-0004 §3）。
- **PR-42** 複数の拡張の規則が競合する場合（同じ開始文字で順序が決まらない場合など）、ホストは競合を検出して利用者に示す。解析結果は決定的にする。
- **PR-43** 拡張パーサーが使えない、失敗した、または時間・メモリの上限を超えた場合、その拡張が無いものとして解析を続け、原文を変更しない。

## 2. 標準Markdownパーサーの構文機能

| ID | 構文 | 既定 | 依存 |
|---|---|---|---|
| `gfm.table` | 表 | オン | — |
| `gfm.strikethrough` | 取り消し線 `~~` | オン | — |
| `gfm.task-list` | タスクリスト `- [ ]` | オン | — |
| `gfm.autolink` | URLの自動リンク | オン | — |
| `footnote` | 脚注 `[^1]` | オン | — |
| `frontmatter.yaml` | ファイル先頭のYAMLフロントマター | オン | — |
| `math` | 数式の区切り `$...$`、`$$...$$` の認識（中身はLaTeXパーサーへ渡す。§4） | オン | — |
| `html` | HTMLの解釈（オフの場合は文字列として扱う） | オン | — |
| `cjk-friendly-emphasis` | CJKの句読点に隣接する強調の区切り記号を強調として認める（`**この文は重要です。**但`）。オフの場合はCommonMarkの規則に従う（ADR-0004 §5） | オフ | — |

フロントマターと数式の区切りはObsidian固有ではないため、標準Markdownパーサーで扱う。数式やMermaidなど、別の言語で書かれた中身の解析は、Markdownパーサーではなく別のパーサーが担当する（§4）。

## 3. Obsidian Markdownパーサーの構文機能

| ID | 構文 | 既定 | 依存 |
|---|---|---|---|
| `obsidian.wikilink` | `[[...]]`、表示文字列 `|`、見出し・ブロックの指定 | オン | — |
| `obsidian.embed` | `![[...]]`、大きさ `|100x145`、PDFの `#page=` `#height=` | オン | `obsidian.wikilink` |
| `obsidian.image-size` | 標準の画像構文の代替テキストでの大きさ指定 `![alt|100](url)` | オン | — |
| `obsidian.block-id` | ブロック識別子 `^id` | オン | — |
| `obsidian.callout` | コールアウト `> [!type]`、折り畳み `+` `-`、入れ子 | オン | — |
| `obsidian.tag` | タグ `#tag`、入れ子 `#a/b` | オン | — |
| `obsidian.properties` | プロパティの型、`tags`・`aliases`・`cssclasses` の解釈 | オン | `frontmatter.yaml`（標準パーサー） |
| `obsidian.alias` | `aliases` による別名でのリンク解決 | オン | `obsidian.properties` |
| `obsidian.highlight` | ハイライト `==text==`、色の絵文字 | オン | — |
| `obsidian.comment` | コメント `%%...%%`（インライン・ブロック） | オン | — |
| `obsidian.inline-footnote` | インライン脚注 `^[...]` | オン | `footnote`（標準パーサー） |
| `obsidian.task-status` | タスクの任意の状態文字 `- [?]` | オン | `gfm.task-list`（標準パーサー） |

### 3.1 対象外

次はMarkdownの構文ではないため、Obsidian Markdownパーサーの範囲に含めない。

- 検索結果の埋め込み（` ```query `）の検索式 → 埋め込み言語のパーサー（§4）
- Basesのコードブロックの中身 → 埋め込み言語のパーサー（§4）
- Mermaidの図の定義とノードからの内部リンク → 埋め込み言語のパーサー（§4）
- `.base` ファイル、`.canvas` ファイル → 別の文書形式拡張（統合開発計画 §4.3）

### 3.2 構文間の解釈の規則（Specで定める事項）

- タグと見出し（`# 見出し` は空白を伴う）、タグとURL中の `#`、タグとリンク先のフラグメントの区別。
- コード（インライン・ブロック）の中の `[[`、`%%`、`==`、`#` は構文として扱わない。
- 表の中のWikilink・埋め込みの `\|`。
- ブロックコメントが閉じていない場合の範囲（Obsidianは以降の全文をコメントとして扱う）。原文は保持し、編集画面では表示する。
- コールアウトは引用の1行目の `[!type]` で判定する。`obsidian.callout` がオフの場合は通常の引用として扱う。

## 4. 埋め込み言語のパーサー

Markdownの中に別の言語（LaTeX、Mermaid、検索式、プログラミング言語など）で書かれた部分がある場合、その中身は言語ごとの別のパーサーが解析する。

### 4.1 要件

- **PR-30** Markdownパーサー（標準・Obsidian）は、別の言語で書かれた部分を「埋め込み領域」として識別し、言語ID・原文の範囲・区切りの種類（インライン・ブロック）を出力する。中身は解析しない。
- **PR-31** 埋め込み領域の言語IDは、数式の区切りでは `latex`、コードブロックでは言語名（` ```mermaid ` → `mermaid`、` ```query ` → `obsidian-query`）とする。言語名の別名（例: ` ```math ` → `latex`）は、埋め込み言語のパーサーが宣言する。
- **PR-32** 埋め込み言語のパーサーは、Markdownのパーサーとは独立した拡張とし、言語IDを宣言して登録する。個別に有効・無効を切り替えられ、構文機能の個別のオン・オフ（§1）も同じ仕組みで持てる。
- **PR-33** 言語IDに対応するパーサーが無い、または無効の場合は、埋め込み領域をそのまま文字列（コードブロックまたは数式の原文）として扱う。Markdownの解析結果は変わらない。
- **PR-34** 埋め込み言語のパーサーの解析結果（構文木、シンタックスハイライト、診断、リンク）は、Markdownの解析結果とは別に保持し、原文の位置（文書全体での位置）で対応付ける。
- **PR-35** 埋め込み言語のパーサーが出すリンク（Mermaidのノードからの内部リンクなど）は、Vaultのリンク索引に、埋め込み言語のパーサーを出典として登録する。
- **PR-36** 描画（数式の組版、図の描画）は、パーサーではなく描画側の拡張が担当する。パーサーは描画に必要な構造を提供する。
- **PR-37** プログラミング言語のコードブロックのシンタックスハイライトは、Language Extension（統合開発計画 §9）が同じ仕組みで提供する。

### 4.2 性能

- **PR-38** 埋め込み言語の解析は、Markdownの解析と分けて遅延実行する。画面に表示される領域、または索引に必要な領域を優先する。
- **PR-39** 埋め込み領域の中身が変わらない編集では、その領域を再解析しない。

### 4.3 初期の埋め込み言語パーサー

| パーサー | 言語ID | 用途 | 時期 |
|---|---|---|---|
| LaTeXパーサー | `latex`（別名 `math`） | 数式（`$...$`、`$$...$$`、` ```math `） | Phase 3以降（Live Previewの数式表示の前） |
| Mermaidパーサー | `mermaid` | 図の定義、ノードからの内部リンク | Phase 8以降 |
| Obsidian検索式パーサー | `obsidian-query` | 検索結果の埋め込み | 検索機能（Phase 8）の後 |
| Basesパーサー | （コードブロックの言語名はP0で確認） | Basesのコードブロック | 未定 |

## 5. プライバシー・セキュリティ

- **PR-20** コメント（`%%...%%`）は表示上隠すだけで、原文・保存内容・検索索引から除外しない。AIへの送信やエクスポート時に、コメントを含めるかどうかを利用者が選べるようにする（既定は含めない）。
- **PR-21** 外部URLの画像・埋め込み（`![...](https://...)`）は、表示のためにネットワークへ接続する。接続はADR-0008の `net.connect` に従い、Vault単位で許可されるまで読み込まない。
- **PR-22** HTMLの描画では、スクリプトの実行、イベントハンドラー属性、外部リソースの読み込みを行わない。
