# Spec: 文書セッション（`document`）

- **状態:** 草案（2026-11-14）。M2（実行計画 §4）の範囲。
- **関連:** 統合開発計画 §4.2、§5.2、§18.4、§18.6／ADR-0002／ADR-0003／[Spec: text-buffer](text-buffer.md)／[P0-02](../research/P0-02-gpui-ime.md)

## 1. 目的と範囲

1つの文書の編集状態を、その文書を表示する複数のビューで共有する（統合開発計画 §4.2「編集・閲覧・プレビューで共通の文書セッション」、§5.2「複数の編集ビューから同一文書を操作」）。

文書セッションが持つもの:

- テキストバッファ（`text-buffer`）と、その編集履歴（全ビューで共有）
- ビューごとの選択範囲と、IMEの変換中の文字列
- 文書の改行コード（§7）
- 保存済みの状態（§8）

範囲外:

| 事項 | 担当 |
|---|---|
| ファイルの読み書き、文字コード、外部変更の検出 | `vault` |
| 自動保存・クラッシュリカバリー | M4。本Specの版で追加する |
| 変更のイベントとしての配送 | `app-core`（操作の戻り値をもとに `app-api` の Event を発行する） |
| 表示上の行（折り返し）に依存する移動（上下の移動、ページ単位の移動）、マウスでの選択 | `ui-gpui`。結果を `set_selections` で設定する |
| 単語単位の移動・削除 | 単語の境界の判定（ICU4X、ADR-0007）の導入時に追加する |
| 文書モデル（解析結果）、`parser-api` | M3で別のSpecとして定める |

文書セッションは同期的に動作し、スレッド・時刻・ファイルを使わない。

## 2. ビュー

- `open_view()` は新しいビュー識別子 `ViewId` を返す。新しいビューの選択範囲は文書の先頭の空の選択（`0..0`）。
- `close_view(view)` はビューの状態（選択範囲、変換中の文字列）を破棄する。変換中の文字列は文書に入れない。
- 存在しない `ViewId` を指定した操作は `UnknownView` エラーとし、状態を変えない。

## 3. 選択範囲

- 選択範囲 `Selection { anchor, head }` はバイト位置の組。`head` がカーソルの位置、`anchor` が選択の起点。`anchor == head` は空の選択（カーソル）。
- 各ビューは1つ以上の選択範囲の列を持つ（複数カーソル。M2のUIは1つだけを使う）。列の中の1つを主選択とする。

不変条件:

- 選択範囲の両端は、内容の範囲内の文字境界である（書記素境界とは限らない。他のビューの編集で書記素の途中になりうる。移動は書記素境界へ揃える。§5.4）。
- 列は始まりの位置の順に並び、重なる選択範囲（空の選択どうしが同じ位置にある場合を含む）は1つにまとめる。まとめた結果に主選択が含まれれば、それを主選択とする。

`set_selections(view, selections, primary)`: 選択範囲の列を設定する。空の列、範囲外・文字境界でない位置、`primary` が列の範囲外の場合はエラーとし、状態を変えない。設定後に不変条件に従って並べ替え・まとめる。

## 4. 内容の変更と選択範囲の補正

- 内容を変える可能性のある操作は、適用した `text-buffer` の `Change` の列を返す（変えなかった場合は空。変換中の文字列の確定を伴う場合は確定と操作の2つ。§6.2）。`app-core` はこれを変更の通知に使う。
- 内容が変わると、すべてのビューの選択範囲と変換中の文字列の位置を `map_offset`（text-buffer §5.5）で補正する。他のビューの選択範囲の両端は `Bias::After` で補正する（他のビューでの挿入位置にあるカーソルは、挿入された文字列の後ろへ移る）。操作したビューの選択範囲は、各操作の規則（§5）で決める。

## 5. 編集コマンド

各コマンドは、指定したビューのすべての選択範囲に対して適用し、全体を1つのトランザクションとして `text-buffer` に渡す（選択範囲の後ろの方から順に範囲置換を並べ、前の選択範囲の位置がずれないようにする）。

### 5.1 文字の入力

`insert_text(view, text)`: 各選択範囲を `text` で置き換える。各カーソルは挿入した文字列の直後の空の選択になる。

- `text` に含まれる改行コードは変換しない（貼り付けなどで受け取った原文をそのまま入れる。§7 は `insert_newline` にだけ適用する）。
- `text` が空の場合は `delete_selection` と同じ。

### 5.2 改行の入力

`insert_newline(view)`: 文書の改行コード（§7）で `insert_text` を行う。

### 5.3 削除

- `delete_backward(view)`（Backspace）: 空でない選択範囲は、その範囲を削除する。空の選択範囲は、カーソルの前の「後退削除の単位」（§5.3.1）を削除する。文書の先頭では何もしない。
- `delete_forward(view)`（Delete）: 空でない選択範囲は、その範囲を削除する。空の選択範囲は、カーソルから次の書記素境界までを削除する。文書の末尾では何もしない。
- `delete_selection(view)`: 空でない選択範囲を削除する。空の選択範囲は何もしない。
- 削除後、各カーソルは削除した位置の空の選択になる。

#### 5.3.1 後退削除の単位（2026-11-14 利用者の決定: コードポイント単位）

カーソルの直前の書記素クラスタを `g`（`prev_grapheme_boundary` からカーソルまで）とする。

- `g` が次のいずれかを含む場合は、`g` 全体を削除する（分けて消すと意味のない状態が残るもの）:
  - CRLF（`g` が `\r\n`）
  - ZWJ（U+200D）
  - 地域指示子（U+1F1E6〜U+1F1FF。国旗）
  - 異体字セレクター（U+FE00〜U+FE0F、U+E0100〜U+E01EF）
  - 絵文字の肌の色の修飾子（U+1F3FB〜U+1F3FF）
  - タグ文字（U+E0020〜U+E007F）
- それ以外は、カーソルの直前のコードポイントを1つ削除する（例: `e` + U+0301 では結合アキュートだけ、`क्ष` では `ष` だけを削除する）。
- カーソルが書記素クラスタの途中にある場合（§3）は、カーソルの直前のコードポイントを1つ削除する。

### 5.4 カーソルの移動

`move_cursor(view, movement, extend)`:

| `movement` | 移動先（`head` の新しい位置） |
|---|---|
| `Left`・`Right` | 前・次の書記素境界 |
| `LineStart`・`LineEnd` | `head` のある行（text-buffer §3.2 の行）の先頭・行区切りの前 |
| `DocumentStart`・`DocumentEnd` | 文書の先頭・末尾 |

- `extend` が真の場合は `head` だけを動かす（選択を広げる・狭める）。
- `extend` が偽の場合は空の選択にする。ただし `Left`・`Right` で空でない選択範囲は、移動せずにそれぞれ範囲の先頭・末尾の空の選択にする。
- 文書の先頭・末尾を越える移動はその位置に留まる。

`select_all(view)`: 選択範囲を文書全体の1つにする。

### 5.5 Undoの区切り

同じビューで、同じ種類のコマンド（`insert_text`、`delete_backward`、`delete_forward`）が続く場合は、履歴の同じ項目にまとめる（`UndoGroup::MergeWithPrevious`）。ただし次の場合は新しい項目にする:

- 間に、そのビューの選択範囲の設定・移動、他のコマンド、他のビューの編集、Undo・Redoがあった。
- `insert_text` の `text` に行区切り（LF・CR）が含まれる。`insert_newline` は常に新しい項目。
- 選択範囲のいずれかが空でなかった（選択範囲の置き換え・削除は単独の項目）。

時刻による区切り（一定時間の入力の停止）は使わない（同じ入力に対して結果を決定的にするため。§1）。

### 5.6 Undo・Redo と選択範囲（2026-11-14 利用者の決定: 編集前の選択を復元）

- 履歴の各項目に、その編集を行ったビューの、編集前と編集後の選択範囲を記録する。同じ項目にまとめた編集では、編集前は最初の編集の前、編集後は最後の編集の後の選択範囲とする。
- `undo(view)`: 現在の項目を取り消し、`view` の選択範囲を、取り消した項目の編集前の選択範囲にする。
- `redo(view)`: 項目をやり直し、`view` の選択範囲を、その項目の編集後の選択範囲にする。
- 記録の無い項目（§8.2 の再読み込み）では、`view` の選択範囲は §4 の補正（`Bias::After`）に従う。
- 他のビューの選択範囲は §4 に従って補正する。
- 記録した選択範囲は、記録した時点の内容に対する位置である。Undo・Redoの後の内容は記録した時点の内容に等しい（text-buffer §6.1）ため、そのまま有効である。

履歴の分岐の操作（`redo_to`・`goto`）は、Undo treeのUIを作る時点で本Specに追加する。

## 6. IMEの変換中の文字列（2026-11-14 利用者の決定: バッファの外で保持）

P0-02の提案に従い、変換中の文字列は確定するまでテキストバッファ・編集履歴に入れない。

### 6.1 状態

各ビューは、変換中の文字列 `Composition { range, text, selected }` を0個または1個持つ。

- `range`: 確定時に置き換えるバッファの範囲（変換の開始時の主選択範囲）。
- `text`: 変換中の文字列。
- `selected`: 変換中の文字列の中の選択範囲（`text` 内のバイト位置。IMEから渡されない場合は `text` の末尾の空の選択。P0-02: Linuxでは渡されない）。

変換中は、主選択範囲は変換中の文字列の位置にあるものとして扱う（§6.3）。M2では変換中の文字列は主選択範囲にだけ置く。複数カーソルでの変換入力は、複数カーソルのUIを作る時点で決める（§10）。

### 6.2 操作

| 操作 | 動作 |
|---|---|
| `set_composition(view, text, selected)` | 変換中でなければ、主選択範囲を `range` として変換を始める。`text`・`selected` を更新する。バッファ・履歴は変えない |
| `commit_composition(view, text)` | `range` を `text` で置き換える1つの項目（`NewGroup`）として適用し、変換を終える。変換中でない場合は主選択範囲を `range` とする（IMEを介さない確定の入力）。カーソルは挿入した文字列の直後。`text` が空の場合は `range` を削除する（変換の開始時に選択していた範囲は、変換の開始で置き換えられたものとして扱う） |
| `cancel_composition(view)` | 変換を終える。バッファ・選択範囲は変換の開始前のまま |

- 変換中に、そのビューで他の操作（選択範囲の設定、移動、編集コマンド、Undo・Redo）を行う場合は、先に現在の `text` で `commit_composition` を行ってから操作する（入力を失わないため）。
- 変換中に他のビューの編集で内容が変わった場合、`range` の始まりを `Bias::Before`、終わりを `Bias::After` で補正し、変換を続ける。

### 6.3 入力用の位置

プラットフォームのテキスト入力（GPUIの `EntityInputHandler`）は、変換中の文字列を含めた文字列に対するUTF-16の位置で問い合わせる（P0-02）。この文字列を「入力用の文字列」と呼ぶ: 変換中はバッファの `range` を `text` で置き換えた文字列、変換中でなければバッファの内容そのもの。

提供する操作（位置は入力用の文字列のUTF-16位置）:

| 操作 | 内容 |
|---|---|
| `input_text_for_range(view, range16)` | 入力用の文字列の範囲の文字列。範囲がサロゲートペアの途中にかかる場合は外側の文字境界へ広げ、入力用の文字列の長さを超える部分は切り詰める |
| `input_selected_range(view)` | 主選択範囲（変換中は `text` の中の `selected`） |
| `input_marked_range(view)` | 変換中の文字列の範囲。変換中でなければ `None` |
| `input_to_buffer(view, offset16)`・`buffer_to_input(view, offset)` | 入力用の位置とバッファのバイト位置の変換。変換中の文字列の内側の入力用の位置は、バッファでは `range.start` に対応する |

## 7. 改行コード（2026-11-14 利用者の決定: 文書の既存の改行に合わせる）

- 文書の改行コードは、セッションの作成時（と §8.2 の再読み込み時）に、内容の最初の行区切りで決める: CRLF、LF、CR のいずれか。行区切りが無い場合はLF。
- `insert_newline` だけが使う。それ以外の操作は改行コードを変換しない（原文の保持。text-buffer §2）。

## 8. 保存済みの状態

### 8.1 未保存の判定

- セッションは「保存済みの履歴の項目」を持つ。作成時は根（読み込んだ内容）。
- `is_dirty()`: 現在の履歴の項目が保存済みの項目と異なる場合に真。Undoで保存済みの項目へ戻ると偽になる。
- `save_point()`: 現在の内容のスナップショットと、現在の履歴の項目を返す。`vault` はスナップショットを書き込み、成功した後に `mark_saved(id)` を呼ぶ。書き込みの間に編集が続いても、`id` の項目が保存済みになる（その後の編集があれば未保存のまま）。

### 8.2 外部での変更の再読み込み

`reload(text)`: 内容を `text` に置き換える（text-buffer §9-4: Undo可能な1つの項目）。

- 置き換えは、現在の内容と `text` の共通の先頭・末尾（文字境界で揃える）を除いた1つの範囲置換とする。内容が同じ場合は内容・履歴を変えない。
- 置き換えた後の項目（内容が同じ場合は現在の項目）を保存済みにする。改行コード（§7）を決め直す。
- 変換中の文字列はすべて取り消す（`cancel_composition`）。

## 9. 不変条件と検証

不変条件:

- §3 の選択範囲の不変条件が、すべての操作の後に成り立つ。
- 変換中の文字列はバッファ・履歴に影響しない（`set_composition` と `cancel_composition` の前後で、内容・版・履歴が同じ）。
- 失敗した操作は状態を変えない。

テスト:

- 例のテスト: §5 の各コマンド、§5.3.1 の各規則（CRLF、ZWJ連結、国旗、異体字セレクター、結合文字、結合子音、ハングルの字母）、§5.5 の区切り、§5.6 の選択範囲の復元、§6 の変換入力の流れ（P0-02で記録した「にほんご」→「日本語」、変換中の削除）、§7、§8。
- Property-based Testing: 任意のビュー・コマンドの列の後で、不変条件が成り立つ。任意の列の後でUndoをすべて行うと最初の内容に戻り、操作したビューの選択範囲が最初の編集の前の選択範囲になる。
- 2つのビューの交互の編集で、他のビューの選択範囲が編集の内容に追従する。

## 10. 決定事項と未決の事項

利用者の決定（2026-11-14）:

1. 変換中の文字列はバッファの外で保持する（§6）。
2. 後退削除はコードポイント単位。ただし分けて消すと意味のない書記素クラスタは全体を消す（§5.3.1）。
3. Undo・Redoで、編集前・編集後の選択範囲を復元する（§5.6）。
4. 改行の入力は文書の既存の改行コードに合わせる（§7）。

本Specの草案で定めた事項（利用者の確認を求める）:

- §5.3.1 の「全体を消す」書記素クラスタの条件。
- §5.5 のUndoの区切り（時刻を使わない規則）。
- §6.2 の、変換中に他の操作を行う場合は先に確定する規則。

未決:

- 複数カーソルでの変換入力（§6.1）。
- 履歴の分岐の操作（`redo_to`・`goto`）での選択範囲（§5.6）。
