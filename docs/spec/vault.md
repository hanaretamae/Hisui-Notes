# Spec: Vault（`vault`）とファイルシステム（`platform`）

- **状態:** 採用（2026-11-14）。M2（実行計画 §4）の範囲。
- **関連:** 統合開発計画 §8.1、§8.2／ADR-0002／ADR-0008 §2・§7／[NFR](../requirements/non-functional.md)「保存の安全性」／[Spec: text-buffer](text-buffer.md) §2／[Spec: 文書セッション](document-session.md) §8

## 1. 目的と範囲

Vault（ノートを置くディレクトリ）を開き、その中のファイルを一覧・読み込み・保存する。

M2の範囲:

- Vaultを開く、ファイルの一覧（§4）、テキストファイルの読み込み（§5）、保存（§6）

範囲外（後続の版で追加する）:

| 事項 | 時期 |
|---|---|
| ファイル・フォルダーの作成・名前の変更・移動・削除 | M3以降 |
| 外部での変更の検出（監視）。保存時の衝突の検出（§6.2）はM2で行う | M4 |
| リンク索引 | M3 |
| 権限の検査（ADR-0008のPermission Broker） | 拡張・MCP等の主体が加わる時点。M2の主体は利用者のみ |
| Android・iOSのファイルアクセス（SAF等） | Phase 9。§3 のトレイトを各OS向けに実装する |
| UTF-8以外の文字コード | 利用者の決定（2026-11-14）により対象外。必要になった時点で検討する |

`vault` は文書セッションに依存しない。読み込んだ文字列で `DocumentSession` を作り、`save_point` のスナップショットを保存する組み立ては `app-core` が行う。

## 2. Vault内のパス（`VaultPath`）

Vaultの根からの相対パスを、`/` 区切りの文字列で表す（統合開発計画 §8.1）。

- 各要素は空でなく、`.`・`..` でなく、NUL・`/`・`\` を含まない。先頭・末尾の `/`、連続する `/` を含まない。
- これに反する文字列は `InvalidPath` とする（Vault外を指すパスを作れない。ADR-0008 §2）。
- Unicode正規化・大文字小文字の変換をしない（原文の保持）。同一性は文字列の一致で判定する。ファイルシステムが大文字小文字・正規化の差を同一視する場合（macOS・Windows）の扱いは、各OSの再開時に定める。
- 根そのものはファイルとして扱わない（空の `VaultPath` は作れない）。

## 3. ファイルシステムの抽象（`platform::FileSystem`）

`vault` はOSのファイル操作を `platform` のトレイトを通して使う（ADR-0002）。テストではメモリ上の実装に差し替える。

| 操作 | 内容 |
|---|---|
| `read(path)` | ファイルの内容（バイト列） |
| `read_dir(path)` | ディレクトリの要素（名前、種類）。順序は不定 |
| `kind(path, follow)` | 種類（ファイル、ディレクトリ、シンボリックリンク、その他）。`follow` が偽ならシンボリックリンク自体の種類 |
| `write_atomic(path, data)` | §6.1 の方式で置き換える |

パスはOSの絶対パス。エラーはOSのエラーの種類と、文書の内容を含まないメッセージで返す。

## 4. Vaultを開く・一覧

- `Vault::open(root)`: `root` がディレクトリ（シンボリックリンクの先を含む）でなければエラー。
- `list()`: Vault内の通常のファイルを再帰的に列挙し、`VaultPath` の昇順で返す。
  - 名前が `.` で始まるファイル・ディレクトリは含めず、ディレクトリの中も辿らない（2026-11-14 利用者の決定。Obsidianと同じ）。パスを直接指定すれば読み込める（§5）。
  - シンボリックリンクは含めず、辿らない（§5、ADR-0008 §2）。
  - 名前がUTF-8でない、または §2 の要素の条件を満たさない（`\` を含むなど）ファイル・ディレクトリは含めず、「除外した要素」として理由とともに返す（UIが利用者に知らせるため）。
  - ファイルの種類（拡張子）で絞り込まない。絞り込みは呼び出し側で行う。

## 5. 読み込み

`load(path)`: ファイルを読み、テキストとファイルの状態を返す。

- パスの途中の要素と、ファイル自体がシンボリックリンクの場合は `Symlink` エラー（M2ではシンボリックリンクを開かない。Vault外を指すことの検査と、保存時の置き換えでリンクがファイルに変わることを避けるため）。
- ファイルが存在しない場合は `NotFound`、通常のファイルでない場合は `NotAFile`。
- 内容がUTF-8として正しくない場合は `NotUtf8 { valid_up_to }` とし、開かない（2026-11-14 利用者の決定。置き換えて開くと保存時に原文を失うため）。
- 先頭のBOM（EF BB BF）は外し、「BOMあり」を状態として保持する（2026-11-14 利用者の決定）。BOMの後ろのバイト列は変換しない（改行コード・正規化を含む。text-buffer §2）。
- ファイルの状態 `FileState`: BOMの有無、内容（BOMを含むバイト列）の長さとハッシュ値。保存時の衝突の検出に使う。

## 6. 保存

### 6.1 書き込みの方式（NFR「保存の安全性」）

`write_atomic` は、保存中の異常終了で原文を失わないように置き換える:

1. 同じディレクトリに一時ファイルを新規に作る（名前は `.` で始め、一覧に現れないようにする）。
2. 内容を書き、ディスクへの書き出しを待つ（`fsync`）。
3. 既存のファイルの権限（パーミッション）を一時ファイルに写す。
4. 一時ファイルを元のファイル名へ置き換える（同じファイルシステム内の `rename`）。
5. ディレクトリの書き出しを待つ（対応するOSのみ）。

途中で失敗した場合は一時ファイルを削除し、元のファイルを変えない。

置き換えにより、元のファイルのハードリンク・拡張属性・所有者は引き継がれない（M2では扱わない）。

### 6.2 衝突の検出（2026-11-14 利用者の決定: 保存せず衝突として通知）

`save(path, text, expected)`:

1. ディスク上の現在の内容を読み、長さとハッシュ値を `expected`（読み込み時または前回の保存時の状態）と比べる。
2. 異なる場合は書き込まず `Conflict { kind: Modified }` を返す。ファイルが無い場合は `Conflict { kind: Deleted }`。
3. 同じ場合は、`expected` のBOMの有無に従ってBOMを付け、`text` を書き込む（§6.1）。新しい `FileState` を返す。

`save_overwrite(path, text, bom)`: 衝突を利用者が確認して上書きを選んだ場合に使う。比較せずに書き込む（ファイルが無い場合は作る）。

- 比較から置き換えまでの間に外部で変更された場合は検出できない（ファイルのロックを使わない）。
- 衝突時の再読み込みは、`load` の結果で文書セッションの `reload` を呼ぶ（文書セッション §8.2）。

## 7. エラー

| エラー | 意味 |
|---|---|
| `InvalidPath` | §2 の条件に反するパス |
| `NotFound` | ファイルが無い |
| `NotAFile` | 通常のファイルでない（ディレクトリなど） |
| `Symlink` | パスの途中またはファイルがシンボリックリンク |
| `NotUtf8 { valid_up_to }` | UTF-8として正しくない（BOMを除いた位置） |
| `Conflict { kind }` | 保存時の衝突（`Modified`・`Deleted`） |
| `Io { kind, message }` | その他のOSのエラー |

エラーにはVault相対パスを含め、文書の内容を含めない（ADR-0008 §6・§8）。

## 8. 検証

- `VaultPath`: 正しいパスの受理、`..`・`.`・空の要素・`\`・NUL・先頭や末尾の `/` の拒否。Property-based Testingで、受理したパスを根に連結した結果が常に根の内側にある。
- 一覧・読み込み・保存: メモリ上のファイルシステムで、§4〜§6 の各規則（隠しファイル、シンボリックリンク、除外した要素、BOM、UTF-8でない内容、衝突、上書き）。
- `write_atomic`（デスクトップの実装）: 一時ディレクトリの実ファイルで、内容の置き換え、権限の維持、一時ファイルが残らないこと、書き込みの失敗時（書き込めないディレクトリ）に元のファイルが変わらないこと。
- 異常終了の再現（電源断）は自動化しない。

## 9. 決定事項と未決の事項

利用者の決定（2026-11-14）:

1. UTF-8のみを開く。正しくない内容は開かずに通知する（§5）。
2. BOMは外して保持し、保存時に戻す（§5、§6.2）。
3. 保存時に外部での変更を検出したら、保存せず衝突として通知する（§6.2）。
4. 名前が `.` で始まるファイル・ディレクトリは一覧から除外する。パスを指定すれば開ける（§4）。

草案で提案し、利用者が推奨案として承認した事項（2026-11-14）:

5. シンボリックリンクは一覧に含めず、開かない（§4、§5）。
6. `VaultPath` で `\` を禁止する（Windowsとの互換のため。Linuxで `\` を含む名前のファイルは除外した要素になる）。
7. 衝突の検出は内容の比較（長さとハッシュ値）で行い、更新時刻を使わない（更新時刻の精度や同期ツールによる変更に左右されないため）。
